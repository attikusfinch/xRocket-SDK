# Новая сессия SDK

## Автоматический режим

Пользователь включил схему «координатор → отдельный исполнитель → независимое
review → commit/push → следующая карточка», с проверкой каждые 5 минут.
Правила и остановки — в [workflow/AUTOPILOT.md](workflow/AUTOPILOT.md).
Локальное состояние и текущие worker/reviewer IDs — `workflow/.autopilot/state.json`;
оно не коммитится и не входит в sdist. Итоги review сохраняются в `workflow/reviews/`.
При активном worker не запускай параллельную ручную работу в этом checkout.

Координатор обрабатывает только очередь, зафиксированную при включении, затем
останавливается. Команда пользователя «останови цикл» отключает будущие запуски;
«пауза» приостанавливает расписание. Текущий рабочий чат остаётся виден в приложении.
Для локального исполнения компьютер и приложение должны оставаться включёнными.

Ниже сохранён ручной способ работы, если автоматический режим выключен.

Открывай корень репозитория SDK в новой сессии. В текущем workspace это
`F:\xrocket-pay\xrocket-sdk`. Можно остаться в `F:\xrocket-pay`: там есть локальный
`AGENTS.md`, указывающий на SDK. Этот внешний файл не входит в репозиторий;
при клонировании достаточно `AGENTS.md` в корне SDK. Глобальные настройки Codex
не менялись. В приведённых промптах замени путь, если клонировал в другую папку.

Вставляй один и тот же промпт:

```text
Работаем над SDK в F:\xrocket-pay\xrocket-sdk.
Прочитай AGENTS.md и START.md проекта. Выполни следующую доступную задачу
по workflow/tasks.json. Если есть in_progress — продолжи её.
Одна задача за эту сессию. Доведи её до проверенного результата и сохрани
handoff, статусы и контекст для следующей сессии. Следующую задачу не начинай.
```

Для выбора вручную замени «следующую доступную» на конкретный ID, например `P001`.
Готовые промпты для продолжения, review и новой задачи — в
[workflow/PROMPTS.md](workflow/PROMPTS.md).

## Где находится контекст

| Файл | Назначение |
|---|---|
| [AGENTS.md](AGENTS.md) | Короткие постоянные правила и завершение сессии |
| [workflow/STATE.md](workflow/STATE.md) | Что реально сделано и что ограничено |
| [workflow/DECISIONS.md](workflow/DECISIONS.md) | Решения с причинами и статусом |
| [workflow/tasks.json](workflow/tasks.json) | Единственная очередь: статусы, зависимости, ссылки |
| `workflow/tasks/<ID>.md` | Результат одной сессии, scope, контекст, критерии |
| `workflow/handoffs/<ID>-<NN>.md` | Что конкретно произошло в завершённой сессии |

Карточки не дублируют статусы. Выполненные задачи не удаляются. Агент читает
только нужный контекст, а новые результаты пишет в файлы до завершения чата.

| Статус в очереди | Что делать |
|---|---|
| `todo` | Доступна, когда все зависимости done; первой берётся по порядку JSON |
| `in_progress` | Продолжить этот ID после завершения предыдущей сессии |
| `blocked` | Причина и нужный ввод в handoff; после устранения вернуть todo/in_progress |
| `done` | Критерии выполнены, проверки и ограничения записаны в handoff |

## Просмотр очереди без запуска агента

Из корня SDK, используя Python 3.11+:

```powershell
.venv\Scripts\python.exe tools\session.py next
.venv\Scripts\python.exe tools\session.py prompt P001
.venv\Scripts\python.exe tools\session.py review BASE
.venv\Scripts\python.exe tools\session.py check
```

На Unix используй `.venv/bin/python`. Скрипт работает на standard library, поэтому
можно запустить любым установленным Python 3.11+. Он печатает промпт, проверяет
очередь v2 и отдельное покрытие 25 Pay / 26 Exchange операций карточками; сам код
не меняет и сессии не создаёт. Ключ операции — `product/method/path`; один owner
внутри каждого продукта, даже если method/path совпадают. Это planned coverage,
включая будущие contract gates, а не проверка наличия методов SDK.
Exchange X002–X014 созданы в X001 и остаются вне сохранённого scope autopilot;
само появление todo карточек не разрешает координатору расширять этот scope.

У каждой задачи есть проверяемый конец; это единица результата, а не лимит времени
или токенов. Если сессия оборвалась, не начинай следующую задачу: используй handoff
и продолжи тот же ID. Если handoff не успел сохраниться, восстанови состояние из
файлов и проверок, не объявляя старую работу завершённой по одному статусу.

## Как это устроено в Codex

`AGENTS.md` — поддерживаемая точка входа для инструкций проекта. Порядок поиска
зависит от project root и текущей папки; поэтому добавлены точки входа и в workspace,
и в SDK. Это не скрытая память между чатами: состояние хранится в обычных файлах.
Источник: [официальная OpenAI documentation об AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
