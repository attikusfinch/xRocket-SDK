## Finding: P2 nested epoch coercion

Location: `src/xrocket/pay/models/webhooks.py:40`, where known invoice/payment
webhook data reuse REST DTOs. The envelope date-time guard does not cover known
nested date-time wire fields before Pydantic converts them.

Reproduction on a valid synthetic `payment_status_changed` envelope: replace
`data.payment.finalizedAt` with JSON number `1800000000` or string `"1800000000"`,
then sign those exact bytes with the synthetic webhook secret. The safe decoder
accepts the known payload and converts either value to
`2027-01-15T08:00:00+00:00`. Consequently `payment.finalized_at is not None` becomes
true for a malformed date-time value. Numeric `invoice.createdAt` and known
transaction dates also coerce. Signature verification itself remains correct.
The review-owned ignored probe `.tmp/review-p017-independent-probe.py` reproduced
these cases; this file is local evidence, not a required repository artifact.

Requested fix: validate all known nested webhook date-time wire values before DTO
coercion, with signed regressions rejecting numeric and numeric-string values as
`WebhookPayloadError`. Cover payment finality, invoice dates and known transaction
dates, plus the other known webhook payload date fields. Keep valid aware strings,
nullable pending values, existing REST public behavior, unknown extra/raw fields
and future event fallback. Do not impose date validation on arbitrary unknown data.
Preserve verification-before-parsing and safe diagnostics.
