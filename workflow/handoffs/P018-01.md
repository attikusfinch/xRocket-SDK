## Решения и контракт

См. [D033](../DECISIONS.md), [полный ledger](../../spec/pay-readiness-2026-10-18.md).
Pay offline scope достаточен для отдельного Exchange discovery, а не production
certification. X001 должна независимо исследовать Exchange sources/auth/REST/WS,
DTO и pagination; Exchange здесь не реализован и его будущая совместимость не обещана.

Сохранены и раскрыты существовавшие policies: GET принимает любой2xx с валидным
DTO при OAS200, writes exact200/201, DELETE строго пустой; shared total optional
int/None против OAS required number, response Money допускает finite int/Decimal
как reader tolerance, часть optional response fields допускает null. Это не новые
server facts. Nullable overrides, точность/лимиты, 4KB metric, PAY-008/009/010/016/017,
ID priority, deduplication/replay/finality server guarantees остаются открытыми.

Проверены реальные изоляция core/Pay/Exchange, public class identity и sync/async
сигнатуры, pooling/ownership/close, timeout/auth isolation, отсутствие скрытых SDK
retries/redirects/auto-pagination/lookup/fanout. HTTP transport context доступен
явно, webhook safe-path errors очищают cause/context; raw/dumps/traceback locals
не объявлены безопасными для общего журналирования.

Webhook secret отдельно от JWT, исходные bytes проверяются до JSON, unknown
type/event/status не означает успех. Payment finality — finalized_at, отдельно
от paid. Повтор/out-of-order возможны; dedupe только приложением по верхнему
delivery id в durable business transaction, не invoice/payment/transaction ID.
