## Решения и контракт

См. [D024](../DECISIONS.md), [Pay contract](../../spec/pay-api.md),
[architecture](../../spec/architecture.md). Источник — сохранённый Current OAS,
точные POST/PUT/DELETE `/api/v1/cheques`, ChequeCreateRequestDto,
ChequeUpdateRequestDto и nested request schemas. Snapshots не менялись.

- Все три mutation paths plural, success только 200; create/update требуют JSON
  Cheque, delete требует zero bytes (PAY-014). Любой другой 2xx или повреждённый
  ответ даёт ResponseValidationError. Одна попытка без redirects/retries.
- Create: обязательны asset и finite Decimal/decimal string amount; JSON amount
  остаётся строкой, без float/округления. Optional client ID max50, password max100,
  description max1000, target max100. Request target enum точный, target pair
  обязателен вместе. Callback/URL поля max500; payload object. OAS не задаёт
  minLength/monetary bounds, prose4KB metric не угадывается.
- Update schema содержит только optional description max1000. `{}` отправляется
  при omission, `""` очищает, explicit None запрещён, как и прочие non-nullable
  request поля. Amount/password/IDs/response extras в update body запрещены.
- Update/delete используют прежний cheque ID helper: непустые строки 1–100,
  оба ID передаются без обещания приоритета. Create max50 не переносится на query.
- Password хранится SecretStr и скрыт из repr; обычные Python/JSON dumps маскируют
  его, в том числе после model_construct/mutation. Wrap validation удаляет input
  из field/model errors и их structured errors/json, включая sibling/target/null
  failures. HTTP/timeout/schema сообщения общие; SDK body не журналирует.

Границы явного доступа: `get_secret_value`, outbound bytes и raw server
`APIError.problem` сохраняют данные по назначению и не предназначены для логов.
Ошибки Pydantic парсинга произвольного malformed JSON до model validators —
внешняя граница DTO parsing, не путь отправки SDK (ресурс принимает готовый DTO).
Новых live guarantees или upstream overrides не введено.
