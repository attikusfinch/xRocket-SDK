## Решения и контракт

Основание — сохранённый Current OAS: InvoiceWebhookDto,
InvoiceStatusChangedWebhookDataDto, PaymentStatusChangedWebhookDataDto,
ChequeWebhookDto, PayoutWebhookDto, WithdrawalWebhookDto и Pay spec §8.
Snapshot не редактировался; Legacy не используется.

- Envelope id/timestamp/type/data обязательны. Id/type строго строки; timestamp
  aware date-time string с исходным offset/долями секунды, отдельно от signing
  timestamp header. Точные known type names берутся из schema names/examples.
  Unknown type string допускает любое JSON data для будущего контракта.
- Known invoice event требует свой variant: invoice-only не требует payment,
  payment_status_changed сохраняет typed payment. Unknown invoice event string
  даёт UnknownWebhook целиком с raw data без валидации будущих invoice/payment.
  Missing/nonstring event, malformed known payload/transaction и плохой envelope
  отвергаются как WebhookPayloadError, никогда не скрываются fallback.
- Переиспользованы Invoice/InvoicePayment/Cheque/Payout/Withdrawal и transaction
  модели с PAY-004–007/011: точные Decimal, camel aliases, aware timestamps,
  nullable pending fields, optional payment.id, unknown statuses/extra fields.
  Finality — `payment.finalized_at is not None`; paid/failed helpers и
  финансовые выводы по имени события/unknown status отсутствуют.
- JSON policy SDK: UTF-8, fractional numbers → Decimal, integers → int,
  duplicate keys и nonfinite NaN/Infinity constants запрещены. Обычные errors
  JSON/Unicode/Pydantic не сохраняются в messages/args/cause/context; public
  boundary очищает даже чувствительный ambient caller exception.
- Успешный safe path сохраняет raw_body и отдельный JSON snapshot; raw_payload
  property возвращает новый deepcopy с исходными wire keys/nulls/Decimal.
  DTO mutations не меняют snapshots. Прямые DTO constructors/model_validate
  не аутентифицируют данные и не заполняют raw properties (RuntimeError).
  Wire extras не могут подделать private snapshots. Public parse-only API нет.
- Обычные envelope/invoice data repr/str скрывают все поля и extras. Explicit
  dumps/raw access/вложенные REST DTO могут содержать чувствительные данные;
  сбор traceback locals и явное логирование входов остаются вне гарантии.
- Повторные и out-of-order delivery принимаются независимо внутри окна P016;
  пример dedupe использует только верхний delivery id, не business invoice/
  payment id. Persistent dedupe, порядок, framework server и business handling
  не реализованы.

Read-only помощники изучили контракт, написали tests и проверили реализацию.
Внутренняя проверка нашла два edge case: Pydantic принимал numeric timestamp
strings как epoch, bytes subclass мог подменить JSON через decode override.
Исправлены date-time prefix validation и нормализация subtype через buffer
memoryview(...).tobytes() после HMAC, минуя decode/__bytes__ overrides.
Regressions включены; финальный read-only review fixes — без оставшихся находок.
Это самопроверка worker, независимое acceptance review координатора ещё требуется.
