## Решения и контракт

Основание — только сохранённый Current OAS `#/info/description` и
[Pay spec §8](../../spec/pay-api.md#8-webhooks-current). D030 — в
[DECISIONS](../DECISIONS.md). Snapshot не менялся.

- HMAC-SHA256 ключом прямого webhook secret по **исходным** ASCII timestamp bytes,
  `b'.'`, raw body bytes. Secret str → точный UTF-8, bytes → без изменений;
  никаких JWT fallback/Legacy SHA256(key)/trim. Пустой secret и str surrogates
  отвергаются как SDK configuration policy.
- Header names case-insensitive, values exact: `[0-9]+` timestamp в ms,
  строго `v1`, 64 ASCII hex digits любого регистра. Leading zeros разрешены и
  остаются частью подписи. Дубли signing headers/case variants и склеенные
  malformed values отвергаются; уже потерянные HTTP-адаптером дубли mapping
  восстановить не может. Эту границу обязан учитывать адаптер приложения.
- Signature сравнивается `hmac.compare_digest` как два 32-byte digest. Проверка
  аутентичности предшествует clock/window, JSON parsing отсутствует даже для
  невалидного JSON/не-UTF8/пустого body.
- **SDK policy:** default tolerance 300000 ms, past/future симметрично и inclusive;
  целое ≥0 без bool, 0 требует точного совпадения. clock возвращает целые
  неотрицательные Unix ms, default `time.time_ns() // 1_000_000`; один вызов после
  HMAC. Нет отключения окна или dedupe. Это не гарантия upstream skew/retries.
- Числовое сравнение timestamp не использует int parsing заголовка; произвольно
  длинные leading zeros и большие значения не приводят к conversion leaks.
  Bounds используют точный Decimal(int) независимо от precision, обходя Python
  int decimal digit limit даже для больших локальных clock/tolerance.
- WebhookConfigurationError/HeaderError/SignatureError/TimestampError наследуют
  WebhookError. Исключения не сохраняют входы в args/attributes/cause/context,
  включая ошибку тестовых часов и чувствительный ambient caller exception.
  Сторонний сбор traceback locals/явное логирование входов вне этой гарантии.

Три literal known-answer fixtures подготовлены read-only помощником независимой
RFC2104 ipad/opad реализацией через hashlib, проверенной на RFC4231 case1 и
stdlib hmac.digest: обычный timestamp, ведущий ноль, UTF-8/CRLF body.
Тест их не вычисляет fixture signing helper-ом. Все данные синтетические.
