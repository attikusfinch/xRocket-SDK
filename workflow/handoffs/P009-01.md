## Результат и файлы

Добавлены одинаковые методы обоих клиентов:

- `invoices.create(request=InvoiceCreateRequest(...))` — POST `/api/v1/invoices`,
  только HTTP 200 с JSON Invoice. Typed response — прежний Invoice.
- `invoices.delete(invoice_id=..., client_invoice_id=...)` — DELETE `/api/v1/invoice`,
  только пустой HTTP 200, результат None. Оба метода требуют JWT и делают один send.

Новый `src/xrocket/pay/models/invoice_requests.py` содержит InvoiceCreateRequest,
InvoiceCallbackRequest, InvoiceURLRequest, InvoiceCustomerRequest. Все четыре
экспортированы из `xrocket.pay` и `.models`, response DTO/импорты сохранены.
В `resources/invoices.py` добавлены методы и str check общего identifier helper:
валидные GET inputs не меняются, неверные типы теперь гарантированно отвергаются
до I/O вместо возможной случайной coercion/TypeError.

Добавлен `tests/test_invoices_write.py` (257 cases). Небольшая необходимая правка
за пределами invoice runtime: `_core/serialization.py` помечает required fields
на нормализованной копии после revalidation. Это устраняет найденный review дефект
`model_construct(_fields_set=set(), price_currency='USDT')`, отправлявший `{}`.
Два generic regressions в `tests/test_request_serialization.py` и sync/async invoice
wire regression проверяют required preservation без изменения исходных fields_set.

Обновлены README, architecture, Pay contract/PAY-008/PAY-012 и open questions,
STATE/DECISIONS(D021)/tasks.json. На входе были незакоммиченные P004–P008/P019
результаты, они сохранены. Все остальные runtime .py, historical/live verification
и P008 handoff совпадают byte-for-byte с `.tmp/p009-baseline/`.
Snapshots, transport, errors, прочие ресурсы и dependencies не менялись.
Нового commit/push нет; Git использовался с command-local safe.directory,
прежнее предупреждение о пользовательском ignore не блокирует status/diff.

## Решения и контракт

См. [D021](../DECISIONS.md), [Pay create/delete contract](../../spec/pay-api.md).
Источники: точные POST `/api/v1/invoices`, DELETE `/api/v1/invoice`,
InvoiceCreateRequestDto и InvoiceCallback/Url/CustomerRequestDto сохранённого Current OAS.

- Create требует только price_currency. Decimal/decimal string суммы сериализуются
  строками без округления; float/bool/int/non-finite отклоняются. Одновременные
  price_amount/min_payment запрещены по документированному amount_conflict,
  включая нулевые суммы. Отсутствие обеих допускается по OAS required list.
  PAY-008 missing_invoice_amount/open amount противоречие не объявлено закрытым:
  server acceptance и monetary bounds остаются неизвестными, ошибок API не скрываем.
- Num_payments — strict int 1–1000000, expires_in — strict int без выдуманного
  диапазона, в миллисекундах. Integer-only — SDK policy при OAS number (PAY-012).
  0/переданные значения сохраняются, OAS default3600000 локально не вставляется.
- Client_invoice_id create без maxLength, DELETE ID 1–100. Эти ограничения не
  унифицированы произвольно. Все строки/IDs сохраняются буквально, без trim/case
  conversion/генерации новых IDs; при двух DELETE IDs сервер по описанию выбирает invoiceId.
- Description max1000, callback/redirect URLs max500, остальные request строки
  без выдуманных форматов/minimums. URL/email/UUID/username validators не добавлены.
  Prose4KB для data/payload сохранён как server limit: byte/char/JSON size metric
  не определён, локальный числовой предел не угадан; добавлен open question.
- Nested request objects все optional, их поля тоже; {} валиден. Никакой response
  DTO автоматически не конвертируется в request. Types strict, aliases camelCase,
  extra forbid. Optional default None означает omission, explicit None отвергается
  по non-nullable OAS; внутри JSON payload None остаётся допустимым JSON null.
  Пустые строки/списки/объекты/0 не теряются через truthiness.
- Exact response policies: create200 JSON, delete200 empty. Иной 2xx, malformed JSON
  или непустое DELETE body — ResponseValidationError; non2xx — прежняя HTTP problem
  classification с metadata, без redirects/retries. Публичные read методы совместимы.
- Core fix касается только normalized clones: required fields всегда идут в wire,
  optional omission и исходные DTO/fields_set сохранены, в том числе внутри Any/dict/list.

Модели и основной тестовый файл написаны отдельными агентами; основной агент
прочитал изменения, сделал resources/exports/core fix и выполнил общие проверки.
Независимый review нашёл required-fields_set defect, затем повторил исходный
и nested probes и подтвердил исправление. Оставшихся actionable находок нет.
