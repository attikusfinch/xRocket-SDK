## Решения и контракт

См. [D019](../DECISIONS.md) и [health/PAY-018](../../spec/pay-api.md).
OAS требует четыре поля; P007 live показала HTTP 200 только с status.
Override разрешает отсутствие каждой component collection независимо:

- Missing → None: состояние компонентов неизвестно.
- Provided [] → []: явно сообщена пустая коллекция.
- Provided nonempty list → прежние typed HealthComponent; malformed items отвергаются.
- Explicit null отвергается: live подтвердил omission, не nullability.

Default None намеренно не валидируется; validator применяется только к переданным
значениям. Не включать validate_default в общей response config без пересмотра
этой policy. Отсутствующая error collection не означает, что компоненты исправны.
Нового success helper и подстановки выдуманных пустых массивов нет.

Python Optional и сгенерированная JSON Schema допускают None шире runtime для
явно переданного null. Это read-модель с missing sentinel: для lossless повторной
валидации/сериализации исходного shape применять `model_dump(exclude_unset=True)`.
Обычный dump включает default None и не является эквивалентом исходного wire
payload. Эта граница отражена в spec/README и проверена regression test.

Независимый read-only review runtime/policy: actionable проблем нет;
указанные serialization/schema границы рассмотрены и задокументированы.
Другой агент изменил два health test-файла, основной агент добавил roundtrip
assertions и минимальный payload offline harness, затем выполнил проверки ниже.
