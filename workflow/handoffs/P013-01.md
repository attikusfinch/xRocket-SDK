## Решения и контракт

Основания: сохранённый Current OAS POST `/api/v1/mass-payouts`, MassPayouts* DTO,
AppPayoutResponseDto/PayoutCallbackRequestDto; [Pay spec](../../spec/pay-api.md),
[архитектура](../../spec/architecture.md), [D027](../DECISIONS.md).

- Required batch asset/payouts; item требует target/max100, target_type, точный
  RequestMoney amount. Optional client ID/max50, description без schema max,
  callback с callback_url/max500 и object payload. Aliases/strict inputs/extra
  forbid, recursive omission и запрет explicit None сохранены. Money отправляется
  точной JSON string; float/округление/фиксированный scale не вводятся.
- PAY-010: batch request принимает только telegram_user_id по operation summary
  «Telegram users only» и targetType prose «only TelegramUserId». Более широкий
  enum из трёх target types противоречив; это ограниченная SDK policy до уточнения,
  не live утверждение. Single payout не ограничен этой политикой. Response strings
  открыты, включая target_type, payout status, reason type/kind.
- PAY-009: items/maxLength500 на object не считается maxItems. Нет локальных
  minItems/maxItems, splitting или предположения о server limit500. Пустой batch
  и 501 items проверены только offline; принятие сервером не обещается.
- Success и error collections остаются отдельными списками: исходные строки IDs,
  ведущие нули, targets, дубликаты и порядок сервера сохраняются. Request positions
  не используются для matching; ID не подставляется из request при omission в
  response. OAS не даёт error index и не гарантирует общий порядок. Для надёжной
  корреляции вызывающий код должен заранее сохранить уникальные client IDs;
  отсутствующий/повторённый ID не обещает однозначное сопоставление.
- Error item требует target/targetType/amount/reason; reason требует все шесть
  полей type/title/status/detail/instance/kind. Status — strict конечное int/float
  без coercion; ошибки HTTP200 не становятся HTTP exceptions. Неизвестные поля
  сохраняются на всех response уровнях. Некорректные/отсутствующие массивы вызывают
  ResponseValidationError вместо ложного пустого успеха.
- Mixed/all-success/all-error доступны явно. All-error HTTP200 имеет
  has_errors=True/is_partial=False; mixed — оба True. Пустые оба массива не
  объявляются доказательством выполнения items. Общего success bool нет.
- Один HTTP attempt без автоматического retry, replay, single-payout fan-out или
  lookup. Успешные items не повторяются. Timeout оставляет индивидуальные исходы
  неизвестными; явный retrieve по сохранённому ID — отдельное действие. Partial
  failure или not-found не доказывают safe replay. Balance checks/атомарность,
  deduplication scope/retention и replay semantics live не подтверждены.

Внутренняя read-only самопроверка контракта другим агентом не нашла конкретных
замечаний. Автор тестов работал только над новым test file. Это части worker
