## Результат и файлы

Добавлен `pay.invoices.payments(...)` для sync/async, точный
`GET /api/v1/invoice/payments` с обязательным SDK token. Параметры keyword-only:
invoice_id/client_invoice_id, cursor, limit. Переиспользован существующий
identifier helper; оба ID передаются, приоритет invoiceId определяет сервер.
Общая проверка limit извлечена из прежнего invoices.list без смены поведения.

Новый `models/invoice_payments.py` содержит InvoicePayment, InvoicePaymentPayer,
InvoiceInternalTransaction, InvoiceBlockchainTransaction, InvoiceBlockchainDetails,
UnknownInvoiceTransaction и отдельные InvoicePaymentPagination/InvoicePaymentPage.
Все восемь моделей экспортированы через обе публичные точки входа. Page требует
items/pagination.next и не требует total. Один вызов делает один запрос.

В `tests/test_invoice_payments.py` — synthetic fixtures и 157 новых проверок.
README, architecture и Pay spec описывают новый метод и границы подтверждения.
Обновлены STATE, DECISIONS (D014) и очередь. Runtime изменения P003 ограничены
invoice resource, новым модулем моделей и re-exports; transport P002 не менялся.

На входе оставались изменения завершённой P002, они сохранены. Git HEAD всё ещё
`ed70137`; commit/push этого запуска не выполнялись. P002 и P003 выполнены
последовательно по новому явному запросу пользователя продолжать очередь
до приблизительно половины контекста; постоянный AGENTS.md не изменён.

## Решения и контракт

См. D014 в [DECISIONS](../DECISIONS.md) и `invoices.payments()` в
[Pay spec](../../spec/pay-api.md). Использованы только указанные карточкой Current
OAS schemas и их прямые вложенные DTO, без изменения snapshot.

Money сохраняет Decimal precision. Payment id необязателен (PAY-007), finalized_at
— aware datetime/None (PAY-004); у transactions nullable money/currency/finalized_at
по PAY-005. Статусы остаются строками (PAY-011); finality — наличие finalized_at.
Нового success/paid helper нет, неизвестный status не превращается в paid.

Callable tagged discriminator применяется к каждому transaction item (PAY-006).
Точные internal/blockchain выбирают только известную typed-модель; malformed
known objects, отсутствующий или нестроковый type отвергаются. Неизвестная строка
type выбирает UnknownInvoiceTransaction с сохранением raw extras без интерпретации.
Новые wire поля на всех уровнях сохраняются. Payer и blockchain details типизированы.
