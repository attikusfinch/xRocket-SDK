## Решения и контракт

Основание — Current OAS reachable DTO четырёх webhook roots, существующие Pay
models и review finding. Read-only inventory 26 reachable schemas подтвердил:

- Invoice.createdAt required/non-null; expiresAt optional/nullable по PAY-003.
- InvoicePayment.finalizedAt optional/nullable по PAY-004; id остаётся optional.
- Internal/blockchain transaction.createdAt required/non-null; finalizedAt
  optional/nullable по PAY-005. Unknown transaction types сохраняют raw поля.
- Cheque/Payout/Withdrawal и их declared callback/links/url DTO date-time полей
  **не объявляют**. Даты в их extras/callback payload являются unknown raw
  значениями; новые ограничения для них не придумывались.

Новые before validators в webhook DTO проверяют только effective typed fields
по этим путям, затем существующие DTO проверяют aware date-time/required/null.
Корректные строки с offset/fractions, optional omission и nullable pending
сохраняются. Alias precedence совпадает с _ResponseModel: camelCase alias имеет
приоритет, snake_case используется при отсутствии alias; shadow snake key —
raw extra, не дополнительное known поле. Исходный payload guard не мутирует.

Date-looking extras любых известных DTO (включая callback.payload, customer,
links/url, payer, blockchain tx details и не объявленный payment.createdAt),
invoice-only payment extra и future type/event/transaction raw не обходятся.
Public REST DTO по явной границе задачи сохраняют прежний epoch coercion;
это не глобальное изменение REST date policy.

Безопасный путь по-прежнему проверяет исходные bytes P016 до UTF-8/JSON/DTO;
неверная подпись имеет приоритет над malformed payload. Money/aliases/unknown
statuses, snapshots/mutation isolation и redacted repr/args/cause/context,
включая ambient caller exception, сохранены. Dedupe только приложением по
верхнему delivery id; никакой бизнес-обработки/порядка/server adapter не добавлено.
