## Решения и контракт

Основания: точные Current OAS `AppPayoutCreateRequestDto`,
`PayoutCallbackRequestDto`, `AppPayoutResponseDto`, POST `/api/v1/payouts`;
[контракт Pay](../../spec/pay-api.md), [архитектура](../../spec/architecture.md),
[D026](../DECISIONS.md). Новых upstream overrides нет.

- Target/max100, target_type enum `user_id` / `telegram_user_id` /
  `telegram_username`, asset и amount обязательны. Amount — finite Decimal/string,
  отправляется точной JSON string без float/округления/фиксированного scale.
- Client ID optional/max50, description optional без schema maxLength.
  Callback имеет optional callback_url/max500 и object payload. Оба callback
  свойства независимы; пустые строки/объекты сохраняются. Explicit None запрещён
  по non-nullable OAS, omission сохраняется рекурсивно.
- MinLength, positivity/amount bounds, URL format и description max не угаданы.
  Prose payload 4KB не имеет определённой size metric; локальный лимит не вводится.
- SDK не генерирует, не меняет и не добавляет client ID. Duplicate HTTP400
  `/api/problems/payout_client_id_duplicate` остаётся обычным APIError с исходным
  problem; нет скрытой сверки или повтора.
- Timeout означает неизвестный итог: сервер мог создать payout после единственной
  HTTP попытки. Документирован явный `retrieve(client_payout_id=saved_id)` после
  неизвестного результата. Not-found не объявляется доказательством safe retry;
  retention/scope/replay semantics сервером не подтверждены.
- Existing Payout response сохраняет неизвестные status/target_type и extra fields.
  Общие auth isolation, ownership, timeout, redirects=False, pooling и error metadata
  гарантии сохранены. Constructed/mutated/nested request DTO revalidate до I/O.

Внутренняя read-only проверка контракта другим агентом worker не выявила замечаний.
Это самопроверка реализации, не независимое review candidate SHA по AUTOPILOT;
последнее и публикацию выполняет координатор.
