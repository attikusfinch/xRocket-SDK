## Решения и контракт

См. [D028](../DECISIONS.md), [контракт Pay](../../spec/pay-api.md),
[README](../../README.md). Источники — точный POST и
`WithdrawalCreateRequestDto`, `WithdrawalCallbackRequestDto`,
`WithdrawalResponseDto` в сохранённом Current OAS; прямые зависимости
[P008](P008-01.md) / [P006](P006-01.md). P013 принята до этой сессии:
[review evidence](../reviews/P013-01.md).

- Required поля: client ID/max150, network enum TON/BSC/ETH/BTC/TRX/SOL,
  address/max100, asset и RequestMoney amount. Network обязателен, даже при
  schema default TON. Optional comment/max50 и отдельный callback с optional
  callback URL/max500 и JSON object payload. Strict строки, extra forbid;
  omission сохраняется, explicit None отвергается по non-nullable schema.
- Нет выдуманных minLength, asset maxLength, positive/min/max amount или общего
  ограничения precision 9. Свободные строки (в том числе ID) могут быть пустыми
  локально, принятие сервером не подтверждено. Рекомендуется стабильный непустой
  client ID, сохранённый caller до I/O. Деньги finite Decimal/string уходят точной
  JSON string без float/округления; address/asset/comment не нормализуются.
  Payload max4KB в prose без определённой metric не становится guessed validator.
- PAY-016 остаётся явным: create принимает 101–150 символов, retrieve имеет
  отдельный guard 1–100 и отвергает длинный либо пустой client ID. Длинные ID
  не урезаются до 100; lookup для всей create длины не обещается. Для client-ID
  lookup выбирайте 1–100; после успешного create сохраните withdrawal_id.
- PAY-017 остаётся открытым: GET missing-ID guard — локальная SDK policy,
  поведение сервера без ID и приоритет двух ID не подтверждены. Create от этой
  неизвестной GET семантики не зависит.
- RequestTimeoutError не означает подтверждённый failure перевода. Ни retry,
  ни lookup, quotas request, ни polling не запускаются. Явный retrieve короткого
  сохранённого ID — отдельное действие; not-found не доказывает safe replay.
  Срок/scope дедупликации и duplicate semantics сервером не подтверждены.
  Synthetic duplicate-like problem проходит общий APIError без сокрытия/повтора;
  тест не объявляет его type документированной ошибкой upstream.
- Existing HTTP pooling/ownership, auth isolation, redirects=False, explicit
  timeout и shared errors сохранены через P008 transport. Existing response
  network/status остаются открытыми строками, unknown fields сохраняются.

Дополнительный read-only агент проверил schema/runtime и затем docs. Runtime
находок нет; две формулировки исправлены: общая рекомендация lookup теперь
учитывает GET bounds, а разрешение empty strings относится к свободным полям,
не network enum/decimal money. Это worker self-check, а не замена отдельного
независимого review координатора. Другой агент написал только новый test-файл;
основной worker прочитал его и выполнил обязательные общие проверки.
