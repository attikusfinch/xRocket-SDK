## Решения и контракт

См. [D023](../DECISIONS.md) и [Pay contract](../../spec/pay-api.md).
Источник — точный POST сохранённого Current OAS,
`InvoiceCreatePaymentAddressRequestDto`, `InvoicePaymentAddressResponseDto`.
Snapshot не исправлялся вручную; новые live overrides не вводились.

- Обязательный `pay_network` — strict request enum TON/BSC/ETH/BTC/TRX/SOL,
  wire alias payNetwork. Extra fields, None, raw dict и response/чужие request
  DTO отвергаются. Использован прежний revalidating RequestModel serializer:
  mutation/model_construct не обходят проверку; required network не теряется
  даже при пустом fields_set, исходный DTO не меняется.
- Нужен хотя бы один непустой str ID длиной 1–100; оба при наличии передаются
  буквально в query как invoiceId/clientInvoiceId. По описанию OAS сервер
  использует invoiceId при двух ID. PayNetwork остаётся только в JSON body.
- Response требует address/payCurrency/payNetwork/expiresAt. Сеть — открытая
  строка; неизвестные response fields сохраняются. ExpiresAt — aware datetime
  по корректной string/date-time schema именно этого DTO. Missing/null/naive
  отвергаются; PAY-003 для InvoiceDto.expiresAt сюда не переносится.
- MinAmount — прежний Money/Decimal без округления и float intermediary.
  Omission даёт None; explicit null отвергается по non-nullable OAS. Для
  сохранения omission в roundtrip нужен `model_dump(exclude_unset=True)`.
  Политика response Money не менялась, включая integer input и отказ float/bool.
- Success policy строго 201 JSON. Иной 2xx/повреждённый JSON/response shape —
  ResponseValidationError; non-2xx — общий error pipeline с problem/request-id/
  retry-after. JWT обязателен. Один send, без retries, redirects или генерации ID.

Тестовый файл написал внутренний агент; основной worker прочитал тесты,
реализовал runtime/docs/workflow и выполнил общие проверки. Другой внутренний
read-only агент сверил runtime с OAS и выполнил offline probes: findings нет.
Это предварительная самопроверка и не замена независимого review координатора.
