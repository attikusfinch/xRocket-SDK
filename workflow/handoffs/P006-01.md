## Решения и контракт

См. [D017](../DECISIONS.md), [контракт Pay](../../spec/pay-api.md).
Источники — три точных GET в сохранённом Current OAS и WithdrawalResponseDto,
WithdrawalListResponseDto, WithdrawalQuotasResponseDto, WithdrawalCallbackDto.

- Withdrawal required: withdrawal_id/network/address/asset/amount. Status,
  comment, tx_hash, tx_link, callback optional. Response network/status — open str,
  регистр сохраняется. Callback URL/payload optional, payload типизирован как object.
  Неизвестные поля сохраняются, clientWithdrawalId в response schema не объявлен.
- Amount/withdraw_min_size/withdraw_fee — существующий Money → Decimal без float.
  SDK не округляет/не обрезает при чтении; описание upstream о 9 десятичных знаках
  не переносится в decoder. Precision — strict конечное int | float (PAY-012),
  bool/строки/NaN/Infinity не принимаются, fractional number не обрезается до integer.
- List status request enum строго CREATED/COMPLETED/FAIL; даты — aware datetime
  через isoformat с offset и долями секунды, каждая optional, порядок не ограничен.
  Cursor opaque, пустая строка сохраняется, None queries опускаются.
  Limit int без bool и без границ: этот GET OAS не задаёт minimum/maximum/default.
  Один запрос на страницу, даже при next cursor или пустых items.
- PAY-017: ≥1 непустой ID 1–100 — **локальная guard policy SDK**, не факт сервера.
  В OAS оба query optional, missing-ID 400 не документирован; upstream поведение
  без ID остаётся неизвестным. При обоих ID передаются оба, приоритет не обещается.
- PAY-016: create client ID max150 не приравнивается к GET max100. Response
  withdrawalId max50 не ограничивает GET inputs и не ужесточает tolerant decoder.
- Quotas network принимает TON/BSC/ETH/BTC/TRX/SOL; asset — обязательная строка,
  пустая допускается схемой без minLength. Отсутствующие kwargs дают TypeError,
  None/нестроковый asset и неизвестный network — локальный ValueError до сети.
- Optional response поля допускают None по прежнему pattern Pay-моделей без
  заявления о live nullability; generic CursorPage и relaxed total не менялись.

Независимый read-only анализ контракта и review runtime/wiring/exports/документации
не нашли actionable проблем. Отдельный агент написал test-файл; основной агент
прочитал его и выполнил полный набор. Изменения pytest loop scope остались только
в аргументе проверки, постоянная конфигурация проекта не менялась.
