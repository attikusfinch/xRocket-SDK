# P008-01: HTTP write pipeline и отдельная request serialization

Дата: 2026-10-17. Итог: done.

## Результат и файлы

Внутренние SyncTransport/AsyncTransport получили `request(method, path, adapter,
success_statuses=..., body=..., params=..., authenticated=...)` с overloads:
TypeAdapter[T] возвращает T из JSON, None задаёт строго пустой success body.
Методы GET/POST/PUT/DELETE, success statuses задаются явно каждой операцией.
Прежний `get()` API делегирует pipeline с прежним допуском всех 2xx.

Runtime изменён только в `src/xrocket/_core/transport.py`, добавлен
`src/xrocket/_core/serialization.py`: RequestModel, RequestMoney, serialize_request.
Добавлены `tests/test_write_transport.py` (226 cases) и
`tests/test_request_serialization.py` (88 cases). Общие прежние transport tests
не менялись. README, architecture, Pay spec, STATE/DECISIONS(D020)/queue обновлены.

Публичные Pay write resources не добавлены: SDK по-прежнему реализует 15 GET
из 25 операций. Core не импортирует Pay/Exchange. Старые public imports и
response Money/DTO не менялись; новый request foundation импортируется внутренне.
Errors module, client/resources, snapshots, зависимости, live harness и прошлые
verification/handoffs сохранены. Нового commit/push нет.

На входе были незакоммиченные P004–P007/P019 результаты, они сохранены. Сравнение
с ignored `.tmp/p008-baseline/` подтвердило неизменность всех прежних runtime .py,
кроме transport, а также historical/live verification и P019 handoff. Git
использовался с command-local safe.directory; предупреждение о пользовательском
ignore остаётся, но status/diff доступны.

## Решения и контракт

См. [D020](../DECISIONS.md), [архитектуру](../../spec/architecture.md),
[Pay money/missing/null](../../spec/pay-api.md). Весь результат P008 проверен
offline; новые upstream guarantees и live write overrides не вводились.

- RequestModel — отдельный BaseModel, extra forbid, populate_by_name,
  revalidate_instances always. Общий core не навязывает Pay camelCase:
  Field aliases/alias_generator задаст конкретный product DTO.
- RequestMoney принимает только конечный Decimal или decimal string. Float,
  bool, int, invalid/non-finite отклоняются. Decimal сериализуется JSON string
  без binary float, округления или fixed scale; response Money остаётся прежним.
- serialize_request возвращает UTF-8 bytes с aliases/exclude_unset. Missing
  опускается рекурсивно, explicit None/default сохраняются. Исходные DTO и
  fields_set не меняются. Повторно проверяется каждый RequestModel, в том числе
  внутри Any/list/dict и после model_construct/mutation.
- Принимается явный JSON graph (scalars, finite Decimal, dict[str,...], list/tuple,
  RequestModel). Response BaseModel, raw top-level dict body, dataclass/bytes/date
  converters, sets, non-string keys, cycles и non-finite JSON запрещены.
  Вручную подготовленный JSON payload может содержать bool/finite float в
  неденежных полях. Никакие response extras не копируются автоматически.
- Adapter None требует zero bytes, в том числе не допускает whitespace/JSON null.
  Typed adapter требует корректный JSON; TypeAdapter nullable type может явно
  разрешать JSON null отдельно от bodyless policy. Непредусмотренный 2xx вызывает
  ResponseValidationError, non-2xx сохраняет прежние API errors/metadata.
- Success policy — nonempty tuple integer 2xx (bool запрещён), method exact-case.
  Неверная policy/body/DTO не отправляется в сеть. `/health` GET-only, GET body
  запрещён. API paths/query/fragments сохраняют прежние guards.
- Write bytes отправляются application/json, Content-Length отражает фактический
  UTF-8 размер, чужие Transfer-Encoding/Content-Encoding defaults удаляются только
  из request. Injected HTTP client остаётся неизменным. Auth isolation, timeout,
  pooling/ownership, redirects=False и ровно один send сохранены. Retry и
  idempotency keys/ID generation не добавлены.

Независимый read-only review выявил два serializer bypass: изменённый money в
RequestModel под Any и response model под dataclass wrapper. Исправлены recursive
clone/revalidation и strict JSON graph; добавлены 20 regressions сверх исходных 68.
Reviewer повторил оба probes: ValidationError/TypeError, оставшихся находок нет.
Его дополнительное замечание о Content-Encoding учтено с framing regression.

## Осталось и продолжение

Критерии P008 выполнены, пользовательский ввод не нужен. Foundation готов для
конкретных Pay request DTO и write resource методов. Endpoint-specific ограничения,
nullable поля, IDs, response status и body policy задаются в соответствующих задачах,
не угадываются общим core. Для объектов вне явного JSON graph продуктовый DTO должен
подготовить wire значение; implicit generic converters намеренно отсутствуют.

Следующая доступная задача по порядку — **P009**, invoice create/delete.
Она не начата. Следующая сессия: `tools/session.py next`, карточка P009 и handoff
прямой зависимости P008. Offline реализация write resource не разрешает реальные
платежи или live mutations без отдельного явного задания.
