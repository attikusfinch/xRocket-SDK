# Управляемый цикл разработки

Этот чат — координатор. Одна новая рабочая сессия реализует одну карточку;
другая новая сессия независимо проверяет результат. Источник очереди —
`workflow/tasks.json`; этот протокол не заменяет критерии карточек и `AGENTS.md`.
Обычная команда «следующая задача SDK» по-прежнему означает одну задачу.
Автоматические новые сессии создаёт только координатор явно включённого цикла.

## Включение и границы

Пользователь выбрал heartbeat каждые **5 минут** и `git_policy=commit_push`:
после обязательных tests и независимого review коммитить и отправлять в GitHub.
Рабочие сессии делают локальный commit; только координатор отправляет
принятый результат после review. Публикация пакетов и live денежные
операции не входят в этот цикл; остальные ограничения SDK сохраняются.

Область первого запуска — снимок ID: `P010`, `P011`, `P012`, `P013`, `P014`,
`P015`, `P016`, `P017`, `P018`, `X001`. Уже завершённые задачи заново не исполнять.
Новые карточки, в том числе результаты планирования Exchange в X001, автоматически
не добавляются. После этого списка остановиться и сообщить результат.
Изменять область может пользователь; существующий `in_progress` сначала сверить
с фактическими файлами и владельцем сессии. При включении незавершённых ID нет.

Используется локальный проект `7aa7b76e-c19a-4e9c-9649-2cbfa854f6cc`;
его папка — `F:\xrocket-pay`, корень Git и команд SDK — `F:\xrocket-pay\xrocket-sdk`.
В каждом промпте явно указать переход в SDK. Worktree не создавать.
Не задавать `model` и `thinking`: сохранять настроенную модель пользователя.
Для локального heartbeat компьютер и приложение должны оставаться включёнными.

## Состояние координатора

Только координатор пишет ignored `workflow/.autopilot/state.json`.
Это восстановимое служебное состояние, не новая очередь задач и не блокировка ОС.
Изменять файл атомарной заменой; секретов, токенов и API-ответов в нём нет.

| Поле | Смысл |
|---|---|
| `version`, `enabled`, `phase` | Версия 1; включение; текущий переход/ожидание/остановка |
| `project_id`, `coordinator_thread_id`, `automation_id` | Привязки проекта, этого чата и heartbeat |
| `interval_minutes`, `git_policy` | `5` и `commit_push` |
| `scope_task_ids` | Разрешённый снимок ID, без автоматического расширения |
| `active` | `null` либо объект текущего worker/reviewer |
| `history` | Неизменяемые принятые результаты: ID, candidate SHA, verdict и ссылки на сессии |

В `active`: `task_id`, `role` (`worker`/`reviewer`), `thread_id`, `host_id`,
`nonce`, `base_sha`, `candidate_sha`, `attempt`, `cursor`, `worker_thread_id`,
`reviewer_thread_id`; при принятии также `review_path`, `journal_sha` и
`publish_sha`. До получения ID/результата
соответствующие поля — `null`. `attempt=0` — первая реализация, 1 и 2 — исправления.
Обе ссылки сохраняются в `active` при смене роли и затем в принятой записи history;
после перезапуска исправляется тот же ID в прежнем worker.

Фазы: `setup`, `idle`, `dispatching_worker`, `worker_running`, `dispatching_reviewer`,
`reviewer_running`, `correcting`, `recording_review`, `publishing`, `paused`,
`stopped`, `complete`. Незавершённое намерение
запуска восстанавливать до выбора другой задачи. `enabled=false` запрещает новые
диспетчеризации; работающий writer сначала должен закончить или передать состояние.

## Один переход цикла

1. Прочитать runtime, очередь и Git; выполнить `tools/session.py check`.
   Проверить прежнюю сессию до новой записи. Допустим один локальный writer либо
   один read-only reviewer. Пока они активны, координатор не меняет tracked файлы.
   Неизвестные изменения не присваивать себе, не stash/reset и не коммитить.
2. Выбрать первый разрешённый todo с завершёнными зависимостями. Для возобновления
   сначала восстановить текущий ID, не обходить блокер другой карточкой.
   Сохранить `base_sha`, уникальный nonce, фазу намерения и ожидаемый заголовок
   до `create_thread`; заголовок содержит роль, ID и nonce.
3. Создать worker через `create_thread` с local project target и явным SDK path.
   Сохранить возвращённые `threadId`/`hostId`. `clientThreadId` не передавать вместо
   настоящего `threadId`; дождаться регистрации. Об неизвестном результате ниже.
4. Следить через `wait_threads`, передавать cursor как `afterCursor`;
   для быстрого снимка использовать `timeoutMs: 0`. Не опрашивать постоянно
   `read_thread`; читать его для восстановления и деталей результата.
5. По завершении worker проверить handoff, критерии, проверки, очередь и Git.
   `done` — кандидат, ещё не разрешение идти дальше. При разрешённых коммитах
   получить полный candidate commit SHA и чистое дерево; зафиксировать SHA до review.
   Если пользователь позже запретит коммиты, остановить цикл на этом барьере.
   Незакоммиченные изменения не выдавать за проверенный SHA.
6. Создать свежий read-only reviewer тем же протоколом намерения. Он проверяет
   именно candidate SHA и критерии карточки. Во время review код не менять.
   При смене HEAD или dirty tree результат не принимать, сначала выяснить причину.
7. До записи определить и сохранить стабильный `review_path` для reviewer/attempt.
   Сохранить результат в `workflow/reviews/<ID>-<NN>.md`: задача, base/candidate SHA,
   сессии, findings, выполненные проверки, ограничения и verdict. При findings
   закоммитить только review-журнал до возврата worker, сохранив чистое дерево.
   При дефектах отправить конкретные исправления через `send_message_to_thread`
   прежнему worker, увеличить attempt; после него создать нового reviewer.
   Допускается максимум два цикла исправлений, затем остановка с причиной.
8. После accepted того же candidate SHA сохранить `recording_review`, стабильный
   `review_path` для этого reviewer/attempt и намерение публикации, не очищая active.
   При повторе сначала проверить уже существующий журнал: не создавать новый номер
   или повторную history запись. Координатор коммитит только review/docs;
   сохранить SHA этого journal commit и ожидаемый `publish_sha` в active, phase=publishing.
   Проверенный runtime-код должен оставаться тем же, что в candidate SHA.
9. В publishing отправить принятые commits обычным push без force, затем сравнить
   local HEAD и remote main. При неизвестном результате push сначала читать remote:
   равный publish_sha означает успех; ожидаемый ancestor допускает тот же обычный
   push; чужое расхождение требует остановки. Active не очищать до подтверждения.
   После подтверждения append ровно одну accepted запись history с ключом
   task_id+candidate_sha и полями journal_sha/publish_sha/сессии; затем active=null,
   phase=idle. После crash сверять журнал, local/remote SHA и этот ключ, не дублировать
   журнал/commit/history. Только этот завершённый переход открывает следующий ID.
   При ошибке сохранить все checkpoints, выключить цикл и сообщить причину.

## Восстановление и остановка

Если `create_thread` вернул неизвестный результат, не повторять запрос вслепую.
Использовать `list_threads` и `read_thread`, найти точный nonce/роль/ID, восстановить
единственную сессию и её реальный статус. Пока результат неоднозначен, новых
сессий не создавать. После рестарта сверять runtime с Git, handoff и статусом
сессии; сохранённая фаза сама по себе не доказывает завершение.

Heartbeat запускается через `automation_update` как thread heartbeat этого чата.
До завершения настройки и проверки протокола runtime остаётся `enabled=false`.
Каждый запуск восстанавливает состояние и делает один допустимый переход;
дубликат запуска не должен создавать второго writer. Сеанс не считается мёртвым
только потому, что долго не пишет. Пользователь разрешает управление созданными
для этого цикла рабочими чатами; посторонним чатам сообщения не отправлять.

Остановиться при blocker, чужом dirty tree, недоступной обязательной проверке,
лимите сервиса, неоднозначном запуске, неуспехе двух исправлений либо завершении
scope. Причину сохранить и сообщить; при полном завершении выключить heartbeat.
Пока состояние неизменно или не требует действий, молчать. Уведомлять о завершении,
существенном сбое и необходимом вводе пользователя. Старые результаты tests
не заменяют новые обязательные проверки.

## Пауза, остановка и возобновление

- «Пауза»: атомарно enabled=false, phase=paused, сохранить предыдущую фазу в
  resume_phase и active без изменений; через automation_update поставить существующий
  heartbeat в PAUSED, сохранив его остальные поля. Не запускать follow-up/review/next.
- «Останови цикл» либо blocker: enabled=false, phase=stopped, сохранить причину,
  resume_phase и active; heartbeat также PAUSED. Работавший worker может закончить
  текущую карточку, но его завершение не запускает продолжение автоматически.
  Прерывать сам worker только если пользователь отдельно просит остановить и его.
- Явное «возобнови»: проверить реальный статус worker/reviewer, Git и checkpoint,
  устранённость причины. Восстановить resume_phase, enabled=true, тот же heartbeat
  ACTIVE без дубликата. Активный worker не запускается повторно; его результат
  сверяется обычным путём. При неустранённом blocker не имитировать возобновление.
- Полный конец scope: enabled=false, phase=complete, active=null, heartbeat PAUSED;
  единожды сообщить итог. Не создавать автоматически новый scope.
