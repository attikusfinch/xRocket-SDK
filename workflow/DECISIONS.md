# Решения, которые нужны следующей сессии

Это исходные инженерные решения, а не отдельное утверждение пользователем каждого
пункта. Уточнять их внутри разрешённой задачи можно с записью причины и последствий.
Не меняй решение молча и не выдавай предположение за подтверждённый контракт API.

| ID | Решение | Основание / статус |
|---|---|---|
| D001 | Python, один дистрибутив, независимые pay/exchange | Язык выбрал пользователь; границы продуктов — проект архитектуры |
| D002 | Pay Current first, Exchange после Pay, Legacy вне первого релиза | Запрос пользователя о порядке; текущий контракт API отличается от Legacy |
| D003 | PayClient / AsyncPayClient, resource API | Реализованный первый срез, сравнение Stripe/OpenAI |
| D004 | HTTPX + Pydantic 2; Decimal и aware datetime | Реализовано и проверено offline |
| D005 | Общая инфраструктура не импортирует продукты | Граница модулей из spec/architecture.md |
| D006 | Одна страница list, без скрытого auto pagination/retry | Реализовано; новые политики требуют отдельной задачи |
| D007 | SDK token изолирован от default auth внедрённой сессии | Исправлено и покрыто sync/async regression tests |
| D008 | OAS snapshot + явные overrides, без слепой генерации | Обнаружены ошибки типов/nullability/auth и live health shape, см. PAY-001…018 |
| D009 | Одна задача на сессию; состояние в проекте | Явный запрос пользователя 2026-10-17 |
| D010 | Все write contracts сначала проверяются offline | Roadmap не разрешает реальные платежи или публикацию |
| D011 | Pay DTO разделены по существующим ресурсам; response config/Money и pagination остаются в Pay, прежние public imports сохранены | Реализовано в P001; `src/xrocket/pay/models/`, `spec/architecture.md`; [handoff](handoffs/P001-01.md) |
| D012 | Git root — корень SDK, remote attikusfinch/xRocket-SDK, main | Прямой запрос пользователя; remote был пустым, доступ ADMIN проверен. Исходники/spec/workflow включаются, локальные данные исключаются |
| D013 | Публичный health — `health.get()` в обоих клиентах; transport разрешает точный `/health` наряду с `/api/` | Реализовано offline в P002, inline OAS задаёт списки HealthComponent; [handoff](handoffs/P002-01.md); live проверка отложена до P007 |
| D014 | `invoices.payments()` возвращает отдельную page без total; transaction discriminator применяется к каждому item, неизвестный type сохраняется явной raw-моделью, повреждённый known type отвергается | Реализовано offline в P003; PAY-004–007/PAY-011; [handoff](handoffs/P003-01.md); finality определяется finalized_at, не status |
| D015 | Cheques имеют собственные DTO и GET validators: dates принимают только aware datetime, target filters парные, GET IDs до 100; оба ID передаются без обещания приоритета. State и все вложенные ссылки optional, отсутствующий в OAS amount не типизируется | Реализовано offline в P004 по точным GET/response schemas; integer-only limit 1–1000 сохраняет политику SDK; [контракт](../spec/pay-api.md); live cheque records не проверялись |
| D016 | Payout reads используют собственные DTO с обязательным Money amount и открытыми status/target_type; aware date filters и GET IDs до 100, оба ID без обещания приоритета. Limit — int без bool и без диапазона: в этом GET OAS нет min/max/default | Реализовано offline в P005 по точным GET/response schemas; create maxLength 50 и чужие limit bounds не переносятся; [контракт](../spec/pay-api.md); live payout records не проверялись |
| D017 | Withdrawal retrieve требует ≥1 ID 1–100 только как локальный SDK guard (PAY-017), оба передаются без приоритета; create client ID 150 не приравнивается к GET100 (PAY-016). Quotas precision сохраняется strict конечным int/float (PAY-012), деньги — Money, response status optional/open с исходным регистром | Реализовано offline в P006; [контракт](../spec/pay-api.md); upstream missing-ID семантика и live quotas/withdrawals остаются неподтверждёнными |
| D018 | Live harness отделён marker/gate от offline: fixed testnet GET, только явный testnet JWT/ID/quota fixtures, independent skips; private failures без records/URL/token. Неуспешный live health не маскируется, а записывается PAY-018 с follow-up P019 | Реализовано и проверено offline в P007; currencies/rates подтверждены live sync/async, private без JWT skipped; [журнал](../spec/live-verification.md). Health runtime в P007 не менялся |
| D019 | Health component fields могут отсутствовать: missing → None (unknown), явные массивы типизированы, [] сохраняется, explicit null отвергается. Status обязателен, unknown поля/statuses и public imports сохранены; roundtrip missing через exclude_unset | Реализовано в P019 по PAY-018; live health.get sync/async: 2 passed. Live подтвердил omission, не nullability; отсутствие error collection не означает подтверждённое отсутствие ошибок; [контракт](../spec/pay-api.md), [handoff](handoffs/P019-01.md) |
| D020 | Core request использует явные success_statuses и TypeAdapter/None для JSON/строго пустого ответа; get сохраняет все 2xx. Отдельный RequestModel(extra forbid) сериализуется aliases/exclude_unset с recursive revalidation, RequestMoney — finite Decimal/string без float. Response/implicit object conversion в request запрещены | Реализовано offline в P008; без публичных write resources/retries/idempotency generation/live writes; [архитектура](../spec/architecture.md), [handoff](handoffs/P008-01.md) |
| D021 | Invoice create/delete используют отдельные strict request DTO, exact200 JSON/empty policies. Neither amount разрешён по schema, both запрещены по amount_conflict; PAY-008 остаётся открытым. NumPayments/expiresIn strict integer — SDK policy, 4KB metric не угадывается. Required wire fields включаются на нормализованном clone даже при custom fields_set | Реализовано offline в P009, без live mutations; IDs/aliases/миллисекунды/0 сохранены, create ID maxLength не переносится из DELETE; [контракт](../spec/pay-api.md), [handoff](handoffs/P009-01.md) |

| D022 | Управляемый цикл: serial local worker на одну карточку, свежий read-only reviewer на candidate SHA, journal/publish checkpoints, 5 минут, automatic GitHub push после принятия | Пользователь явно выбрал частоту и Git-политику 2026-10-17; scope P010–P018/X001, [протокол](AUTOPILOT.md), [handoff](handoffs/AUTO001-01.md). Live деньги/deploy/PyPI не разрешены |
| D023 | Invoice payment address — `invoices.create_payment_address` с отдельным strict request DTO и exact201 JSON policy. IDs 1–100 остаются query, payNetwork — body enum. Response expires_at required aware datetime, min_amount optional Decimal с отказом explicit null; PAY-003 не переносится с InvoiceDto | Реализовано offline в P010 по точному Current OAS, без live address creation. Unknown response networks/fields сохраняются; [контракт](../spec/pay-api.md), [handoff](handoffs/P010-01.md) |
| D024 | Cheque create/update/delete используют plural path и exact200 JSON/empty policy. Create amount — RequestMoney, client ID max50; query IDs 1–100. Update только description: omission допускает {}, empty string очищает, null запрещён. Password — SecretStr с явным wire context serializer, маскированием обычных dumps/repr и удалением input из field/model validation errors | Реализовано offline в P011 по Current OAS; generic core допускает SecretStr, по умолчанию оставляет masked, не импортирует продукты. Raw outbound bytes/raw server problem доступны явно; live mutations не выполнялись; [контракт](../spec/pay-api.md), [handoff](handoffs/P011-01.md) |

Существенное новое решение добавляй с ID, причиной, затронутыми файлами и статусом
(предложено / реализовано / подтверждено live / заменено Dxxx). Для отменённого
решения сохраняй строку и ссылку на замену. Локальные детали реализации не превращай
в длинную историю обсуждений. Подробные основания уже лежат в specs.
