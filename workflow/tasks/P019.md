# P019: Подтверждённый минимальный health response testnet

## Цель
Исправить несовместимость `health.get()` с живым ответом, обнаруженную P007,
сохранив public imports и поддержку полного Health из Current OAS.

## Прочитать
- `AGENTS.md`, текущие STATE/DECISIONS/tasks.json и handoffs P002/P007.
- `spec/live-verification.md`, PAY-018 в `spec/pay-api.md`.
- `models/health.py`, `resources/health.py`, `tests/test_health.py`, public live smoke.
- Inline OAS schema `#/paths/~1health/get/responses/200/content/application~1json/schema`.

## Входит
- Учесть HTTP 200 testnet `{"status":"ok"}` без info/error/details, подтверждённый
  2026-10-17 в P007. Сейчас обе версии клиента дают ResponseValidationError.
- Выбрать и описать response policy отсутствующих component fields без выдачи
  неизвестного состояния компонентов за подтверждённый успех.
- Сохранить типизацию полного OAS response, unknown fields/statuses, sync/async parity.
- Обновить public health smoke, если он предполагает обязательный error collection.

## Не входит
- Изменение snapshot, auth/transport или подавление live failures через skip.
- Новые endpoints, private credentials, write/webhook/Exchange.

## Приёмка
- Минимальный status-only payload и полный OAS payload читаются обоими клиентами.
- Необязательность и семантика отсутствующих component fields задокументированы.
- Regression tests включают оба shape и malformed status/components.
- Новые live результаты записаны отдельно от исторического первого среза.

## Проверка
- Целевой `tests/test_health.py`, полный offline pytest, Ruff и strict mypy.
- Отдельный opt-in public health testnet GET, если сеть доступна; failure не скрывать.
- Handoff/STATE/DECISIONS и `tools/session.py check` по общему протоколу.

## Источники
- P007 live probe: HTTP 200, JSON object с единственным полем status: str (`ok`).
- `spec/live-verification.md`, PAY-018, текущий OAS без ручных изменений.
