# P004: Чтение cheques: список и один чек

## Цель
Добавить самостоятельный Pay cheques resource с двумя read-only методами.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: inventory №10/13, даты, идентификаторы и cursor pagination.
- Актуальные Pay client/resources/models после P001; patterns существующих invoices.
- `ChequeResponseDto`, `ChequeListResponseDto` и параметры двух GET в snapshot.

## Входит
- GET /api/v1/cheques: fromDate/toDate, targetType/target, state, cursor, limit.
- GET /api/v1/cheque: chequeId/clientChequeId, точный singular path.
- Типизированные cheque, links, callback и URL с учётом optional полей.

## Не входит
- Создание/изменение/удаление cheques, webhook обработка, общая абстракция всех ресурсов.

## Приёмка
- Sync/async имена, аргументы и модели совпадают; snake_case явно даёт wire aliases.
- Не считать необязательный state или amount обязательным вопреки ChequeResponseDto.
- Даты сериализуются по контракту, cursor непрозрачен, missing query опущен.
- Identifier validation основана на конкретных GET schemas, а не скопирована с invoices.

## Проверка
- Создать `tests/test_cheques_read.py` с общей sync/async таблицей.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_cheques_read.py`.
- Проверить минимальный DTO, unknown state, пустую и следующую страницы.
