# P013: Mass payouts и явный частичный результат

## Цель
Представить batch payout как набор успехов и ошибок отдельных элементов.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: inventory №22, partial success, PAY-009/010.
- Актуальные payout request/response модели после P012.
- MassPayoutsCreateRequestDto, MassPayoutsCreateResponseDto и item DTO.

## Входит
- POST /api/v1/mass-payouts и точная сериализация batch items.
- Отдельные типы successPayouts/errorPayouts с сохранением item correlation.
- Задокументировать неподтверждённые batch limit и targetType различия.

## Не входит
- Авторазбиение batch, параллельные payouts, replay batch, угадывание лимита 500.

## Приёмка
- HTTP 200 с item failures не превращается в полную успешную выплату.
- Mixed/all-success/all-error ответы доступны пользователю без потери исходных IDs.
- Не считать ошибочный maxLength на object доказательством maxItems.
- Request policy по target types явно основана на OAS/prose и не обещает live подтверждения.

## Проверка
- Создать `tests/test_mass_payouts.py` для sync/async и трёх вариантов результата.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_mass_payouts.py`.
- Проверить один attempt и отсутствие автоматического retry успешных item.

## Источники
- `#/paths/~1api~1v1~1mass-payouts/post`; MassPayouts* DTO.
- PAY-009, PAY-010; `spec/pay-api.md`: client IDs/partial success.
