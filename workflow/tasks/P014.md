# P014: Создание withdrawal с обязательным client ID

## Цель
Добавить withdrawal create, сохранив явную корреляцию и неопределённость timeout.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: inventory №17, PAY-016/017, withdrawal money/network rules.
- Актуальные withdrawals read resource/models и write pipeline.
- WithdrawalCreateRequestDto и POST operation responses.

## Входит
- POST /api/v1/withdrawals: clientWithdrawalId, network/address/asset/amount, optional fields.
- Отдельный request type и уже созданная response model.
- Объяснить пользователю различие ограничения client ID create=150 и retrieve=100.

## Не входит
- Blockchain confirmation polling, автоматические retries, отправка средств в live.

## Приёмка
- clientWithdrawalId обязателен и не генерируется/заменяется автоматически.
- Длина create ID не урезается молча до retrieve ограничения; проблема видна в docs.
- Суммы строки, network/address/comment не нормализуются по несуществующим правилам.
- После timeout нет второго запроса или заявления о failure перевода без подтверждения.

## Проверка
- Создать `tests/test_withdrawals_write.py` с boundaries client ID и timeout.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_withdrawals_write.py tests/test_withdrawals_read.py`.
- Все monetary tests остаются offline до отдельного поручения на live операции.

## Источники
- `#/paths/~1api~1v1~1withdrawals/post`, `WithdrawalCreateRequestDto`.
- PAY-016, PAY-017; выводы read карточки P006.
