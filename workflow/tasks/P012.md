# P012: Создание одиночного payout

## Цель
Добавить payout create без скрытых повторов денежной операции.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: inventory №14, client IDs и duplicate semantics.
- Актуальные payouts read resource/models, write pipeline и errors.
- AppPayoutCreateRequestDto и его request enums/constraints.

## Входит
- POST /api/v1/payouts: отдельный request type и AppPayout response.
- target/targetType, asset, amount, clientPayoutId, description и callback.
- Документировать lookup по client ID для неизвестного результата timeout.

## Не входит
- Mass payouts, генерация client ID, автоматическая сверка/повтор, live перевод.

## Приёмка
- Amount точен и строковый в JSON; request enum не закрывает response evolution.
- Client ID не меняется автоматически, duplicate API error не скрывается.
- Timeout оставляет неизвестный итог операции; SDK делает ровно один HTTP attempt.
- Обязательные request поля и maxLength соответствуют schema; sync/async совпадают.

## Проверка
- Создать `tests/test_payouts_write.py`, включая timeout без второго запроса.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_payouts_write.py tests/test_payouts_read.py`.
- Никакого реального payout без отдельной явной инструкции пользователя.

## Источники
- `#/paths/~1api~1v1~1payouts/post`, `AppPayoutCreateRequestDto`.
- `spec/pay-api.md`: §7, таблица client IDs.
