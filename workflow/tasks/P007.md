# P007: Opt-in read-only testnet harness и журнал подтверждений

## Цель
Отделить полноту offline чтения Pay от фактических подтверждений живого testnet.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `tests/integration/test_public_live.py`, pytest marker/config в `pyproject.toml`.
- `spec/verification.md`, `spec/pay-api.md`: known issues и live smoke policy.
- Актуальные read resources; токен только из явно используемой testnet env variable.

## Входит
- Расширить публичный smoke health; добавить opt-in приватные GET smoke по готовым ресурсам.
- Private retrieve/payment tests используют явные идентификаторы fixtures из env, без угадывания.
- Записать, что подтверждено, пропущено и остаётся открытым; sanitise fixtures.

## Не входит
- POST/PUT/DELETE, mainnet, получение токена, утверждение live success по mock pass.

## Приёмка
- Обычный pytest остаётся offline; opt-in флаг и отсутствие JWT дают понятный skip.
- Отсутствие конкретного testnet ID не ломает независимые list/app smoke.
- Недоступность testnet при явно включённом live — failure, а не искусственный pass.
- Результат карточки — harness; отсутствие credentials не блокирует его реализацию.

## Проверка
- Расширить `tests/integration/test_public_live.py`; создать `tests/integration/test_private_live.py`.
- Offline: `.venv\Scripts\python.exe -m pytest`.
- Live GET запускать отдельно по `spec/test-plan.md`, с явным включением и без утечки env.

## Источники
- `spec/pay-api.md`: §11–12; `spec/verification.md`.
- Marker `live` должен корректно описывать публичные и приватные read-only проверки.
