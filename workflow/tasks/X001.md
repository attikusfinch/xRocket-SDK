# X001: Исследовать контракт Exchange и спланировать первый срез

## Цель
Начать Exchange с проверенного контракта и одного небольшого следующего результата.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/architecture.md`, `spec/sdk-comparison.md`, результаты P018.
- Официальные Exchange overview/reference и актуальная OpenAPI, найденная по ним.
- `src/xrocket/exchange/__init__.py`, shared core и подтверждённые границы Pay.

## Входит
- Сохранить OAS/источники с датой/provenance, определить окружения/auth/error shapes.
- Составить фактический inventory REST и отдельно описать WebSocket lifecycle.
- Выбрать маленький public REST срез и подготовить новые session cards только по найденным фактам.
- Адаптировать operation registry/checker к Exchange, сохранив отдельную проверку Pay coverage.

## Не входит
- Реализация Exchange клиента, предположительные endpoint lists, объединение Pay/Exchange credentials.

## Приёмка
- Новая spec отделяет доказанные поля/пути от противоречий и открытых вопросов.
- Нужные изменения shared core обоснованы конкретным контрактом, Pay изолирован.
- Новая очередь предлагает один обозримый public REST результат, а не весь Exchange за сессию.
- WebSocket, private account/orders/funding имеют отдельные будущие границы без выдуманных методов.

## Проверка
- Код API не меняется: SDK test suite повторять только если появились реальные изменения.
- Проверить JSON snapshot, ссылки и связность добавленных карточек через workflow tooling.
- Не запускать приватные торговые или денежные запросы.

## Источники
- `https://docs.xrocket.exchange/api/exchange/exchange-api-overview`.
- `https://docs.xrocket.exchange/api/exchange/reference/exchange-rest-api` — проверить актуальность.
