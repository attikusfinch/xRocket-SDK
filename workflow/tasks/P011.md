# P011: Мутации cheques: create, update и delete

## Цель
Завершить один cheques resource тремя операциями записи.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: inventory №9/11/12, client IDs и bodyless DELETE.
- Актуальные cheques read resource и request serializer после P008.
- ChequeCreateRequestDto, ChequeUpdateRequestDto и operation identifier parameters.

## Входит
- POST /api/v1/cheques: create request и Cheque response.
- PUT /api/v1/cheques: identifier query плюс разрешённые update fields.
- DELETE /api/v1/cheques: identifier query и пустой успешный ответ.

## Не входит
- Webhook обработка, массовые cheques, финансовые live запросы и retries.

## Приёмка
- Все три mutation paths plural, retrieve остаётся singular из P004.
- Create amount — decimal string; clientChequeId length и request enums взяты из schema.
- Update не переотправляет response DTO и не добавляет поля, которых нет в update schema.
- Секретный cheque password не попадает в repr/log/errors; пустой DELETE 200 принимается.

## Проверка
- Создать `tests/test_cheques_write.py` с sync/async таблицей методов/paths/body.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_cheques_write.py tests/test_cheques_read.py`.
- Отдельно проверить omission/null policy update request.
