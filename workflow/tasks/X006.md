# X006: Public Exchange REST orderbook snapshot

Статус и зависимости — только в [очереди](../tasks.json). Карточка вне сохранённого
scope `ap-48ca458fcbf2`; REST ownership не означает готовый stream orderbook.

## Результат

Sync/async один GET `/api/v1/orderbook` с отдельным response snapshot DTO.

## Прочитать

- `AGENTS.md`, [REST контракт](../../spec/exchange-api.md),
  [границу WebSocket](../../spec/exchange-websocket.md), [X002](X002.md)
  и handoff X002 из [очереди](../tasks.json).
- Exchange OAS orderbook path, `OrderbookResponse`,
  `ExchangeIncorrectPrecisionExceptionDto`; существующие Exchange query/Decimal helpers.

## Сделать

- Query `symbol` обязателен; `depth` необязателен и имеет values
  5/10/20/50/100/200/500; `precision` — optional string. Не выводить default depth
  из example=10 и не добавлять собственный серверный список precisions.
- Response required: строковый `sequence`, `bids`, `asks`, Decimal totals
  `askTotalAmount` / `bidTotalAmount`. Bids/asks OAS — arrays of string arrays;
  prose описывает price/size. Явно описать решение для лишних/недостающих элементов,
  не выдавать отсутствие minItems/maxItems за fixed tuple contract.
- Exact 200, aliases, Decimal accuracy и неизвестные response fields;
  errors 400 incorrect precision/validation/symbol-not-opened, 404/500 сохранить.

## Вне scope

Применение WS deltas, gap detection, reconnect/resync, сортировка/агрегация книги.
Строковый sequence не превращать в доказательство связи REST/WS последовательностей.

- Общие code/export checks по `AGENTS.md`, workflow/link checks, spec и новый handoff
