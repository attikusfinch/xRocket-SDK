# P017: Типизированные webhook events с fallback для неизвестных

## Цель
Декодировать проверенный webhook в Pay-модели без потери будущих событий.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: invoice/payment events, finality, ordering и delivery ID.
- Verifier P016 и response models P003/P004/P005/P006.
- InvoiceWebhookDto, ChequeWebhookDto, PayoutWebhookDto, WithdrawalWebhookDto.

## Входит
- Envelope id/timestamp/type/data и payload известных Pay webhook types.
- Invoice event variants: invoice_status_changed и payment_status_changed.
- Fallback неизвестного event/type с доступным raw payload после успешной verify.

## Не входит
- Бизнес-обработка платежа, persistent dedupe, гарантии порядка, HTTP server adapters.

## Приёмка
- Unknown event не выдаётся за invalid signature и не считается paid/failed.
- Payment finality использует finalizedAt; неизвестные статусы не ломают decode.
- Повторная/out-of-order доставка допускается; примеры dedupe используют верхний delivery id.
- Invoice-only event не требует payment; event с payment сохраняет его typed DTO.

## Проверка
- Создать `tests/test_webhook_events.py` с valid-signature payload и variant fixtures.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_webhook_events.py tests/test_webhook_signatures.py`.
- Fixtures синтетические, без personal data и реального signing secret.

## Источники
- Current `InvoiceWebhookDto`, `InvoiceStatusChangedWebhookDataDto`, `PaymentStatusChangedWebhookDataDto`.
- `ChequeWebhookDto`, `PayoutWebhookDto`, `WithdrawalWebhookDto`; PAY-004–007/011.
