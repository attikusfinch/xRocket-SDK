# P008: Общий pipeline HTTP-записи и сериализация request DTO

## Цель
Подготовить transport к мутациям до реализации отдельных Pay write endpoints.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `src/xrocket/_core/transport.py`, `src/xrocket/_core/errors.py`, `tests/test_transport.py`.
- `spec/architecture.md`: shared core, money, ownership, retries.
- `spec/pay-api.md`: aliases, missing/null, 200/201 и bodyless DELETE.

## Входит
- Минимальный sync/async pipeline POST/PUT/DELETE с JSON body и explicit response policy.
- Request DTO/serializer: Decimal или decimal string → JSON string, aliases, omission.
- Поддержка пустого успешного тела и типизированного JSON success; read API совместим.

## Не входит
- Публичные write resources, реальная запись в сеть, автоматические retry/idempotency.

## Приёмка
- Float/bool/non-finite money отвергнуты; сериализация не проходит через binary float.
- Missing отличается от explicit null; response extra fields не уходят в request автоматически.
- 200, 201, пустой success, malformed JSON и HTTP problem errors проверены в sync/async.
- Auth isolation, timeout, redirect, ownership и один attempt сохраняются.

## Проверка
- Создать `tests/test_write_transport.py` и `tests/test_request_serialization.py`.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_write_transport.py tests/test_request_serialization.py tests/test_transport.py`.
- MockTransport полностью достаточен; финансовые live tests этой карточке не нужны.
