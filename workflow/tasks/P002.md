# P002: Публичный health и корневой маршрут вне /api

## Цель
Добавить типизированную проверку health через тот же sync/async HTTP pipeline.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: окружения, inventory №1 и правила auth.
- `src/xrocket/_core/transport.py`: сейчас `_request_options` разрешает только `/api/`.
- Актуальные Pay client/resources/models после P001; `tests/test_transport.py`.

## Входит
- `GET /health` без обязательного JWT; один согласованный метод обоих клиентов.
- Типы health/component responses по фактической inline schema.
- Безопасно разрешить /health, сохранив проверки URL, query, fragment и lifecycle.

## Не входит
- Version endpoint Legacy, health retries, новый отдельный HTTP-клиент.

## Приёмка
- URL содержит ровно /health без /api/v1; без токена запрос проходит.
- Sync/async возвращают одинаковую модель, неизвестные статусы/поля читаются.
- Абсолютный URL, protocol-relative URL и внедрение query не обходят guard.

## Проверка
- Создать `tests/test_health.py`; расширить существующий `tests/test_transport.py`.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_health.py tests/test_transport.py`.
- Достаточно MockTransport; live health добавляется отдельно в P007.

## Источники
- `spec/openapi/pay-current.json`: `#/paths/~1health/get`.
- `spec/pay-api.md`: /health расположен вне /api/v1.
