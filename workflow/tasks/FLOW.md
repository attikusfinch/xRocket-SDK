# FLOW: Система старта и передачи контекста между сессиями

## Цель
Обеспечить один ограниченный результат за сессию с воспроизводимым стартом и handoff.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `AGENTS.md`, `START.md`, `workflow/PROMPTS.md`.
- `workflow/STATE.md`, `workflow/DECISIONS.md`, `workflow/tasks.json`.
- `workflow/templates/`, `tools/session.py`, `workflow/handoffs/FLOW-01.md`.

## Входит
- Стартовый промпт, текущие факты, очередь с зависимостями и карточки задач.
- Шаблон передачи результата, продолжение незавершённой задачи, проверка связности.
- Разделение результатов offline tests, live evidence и неподтверждённых предположений.

## Не входит
- Изменение API SDK, реализация следующих карточек и автоматический запуск новой задачи.

## Приёмка
- Новая сессия определяет одну готовую задачу и её критерии без чтения старого чата.
- Очередь покрывает исходные 25 Pay operations ровно по одному владельцу.
- Незавершённая работа восстанавливается из handoff без ложной отметки завершения.

## Проверка
- Проверка workflow выполняется командами из `START.md` и `tools/session.py`.
- Python SDK tests здесь не заменяют проверку ссылок, JSON и зависимостей.
- Закрытие и обновление состояния выполняются по `AGENTS.md`.

## Источники
- `workflow/tasks.json` — единственный источник статусов и зависимостей.
- `spec/pay-api.md` — источник inventory Current Pay.
