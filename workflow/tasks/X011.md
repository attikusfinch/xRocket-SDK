# X011: Contract gate private Exchange Orders

Статус и зависимости — только в [очереди](../tasks.json). Карточка вне сохранённого
scope `ap-48ca458fcbf2`; шесть planned operations — контрактная граница.

## Результат

Уточнённые order contracts и последовательность малых implementation cards;
в этой сессии нет SDK order методов и торговых запросов.

## Прочитать

- `AGENTS.md`, [контракт Exchange](../../spec/exchange-api.md), [X002](X002.md)
  и handoff X002 из [очереди](../tasks.json); официальные order docs через provenance.
- Только OAS GET `/api/v1/orders/active`, GET/DELETE `/api/v1/order`,
  GET `/api/v1/orders/history`, POST `/api/v1/orders/estimate`, POST `/api/v1/orders`;
  их request/response variants, pagination и problem details.

## Сделать

- Проверить четыре request/response варианта: limit, market, stopLimit, stopMarket;
  required size/funds/price/stopPrice, request timeInForce и clientOrderId constraints.
  Market size/funds relation не считать доказанной одним лишь required list;
  выяснить documented mutual/exactly-one semantics либо оставить вопрос.
- Зафиксировать orderId/clientOrderId required-one rule, precedence orderId при обоих,
  max lengths 100/64, unknown response type/status policy и string timestamps.
- Развести success codes: GET/DELETE 200; POST orders/estimate и orders — 201.
  Estimate отдельный authenticated POST, а не разрешение выставлять order.
  Сверить ошибки и timeout outcome; client ID не является доказательством безопасного
  replay, idempotency window или автоматического retry.
- History — numbered page с currentPage/pageSize/totalNum/totalPage, query filters,
  default/max pageSize по OAS; не переиспользовать Pay cursor pagination.
- Разбить реализацию как минимум на read, estimate и mutating boundaries, с отдельными
  DoD для variants; operation ownership перенести новым owners один раз без дублей.

## Вне scope

SDK order implementation, live orders/cancellation/estimate, real secrets, private
trade history без подтверждённого endpoint, WebSocket private orders.

## Готово, когда

- Spec с источниками фиксирует variant matrix, ID/precision/timeout вопросы и
  неподтверждённые guarantees; будущие карточки укладываются в одну сессию каждая.
- У каждого из шести REST contracts один owner; gate после полного переноса не
  дублирует coverage. Новые cards имеют dependencies, mock-only tests и явные границы.
- JSON/provenance/link checks, `tools/session.py check`, handoff по `AGENTS.md` пройдены;
  никакие private торговые запросы не выполнялись.
