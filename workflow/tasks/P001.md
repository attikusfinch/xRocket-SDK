# P001: Разделить Pay-модели по ресурсам с сохранением импортов

## Цель
Подготовить структуру моделей к новым Pay-ресурсам без растущего общего models.py.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/architecture.md`: границы продуктов и public API.
- `src/xrocket/pay/models.py`, `src/xrocket/pay/__init__.py`, ресурсы и импорты тестов.
- После перемещения искать актуальные определения через `rg`, а не старые номера строк.

## Входит
- Заменить небольшой `pay/models.py` пакетом `pay/models/` с явными модулями по ресурсам.
- Отделить базовую response-модель/денежный тип и Pay pagination от DTO ресурсов.
- Сохранить re-export ранее доступных имён из `xrocket.pay.models` и `xrocket.pay`.

## Не входит
- Новые endpoints, смена wire/response поведения, универсальная модель для Exchange.

## Приёмка
- Существующие импорты и шесть методов работают без пользовательской миграции.
- Направления зависимостей не нарушены: core не знает Pay, Pay не знает Exchange.
- В architecture.md отражена фактическая структура без преждевременных пустых абстракций.

## Проверка
- Существующие `tests/test_models.py` и `tests/test_contracts.py`; новые тесты только для нужных гарантий импортов.
- `.venv\Scripts\python.exe -m pytest tests/test_models.py tests/test_contracts.py`.
- Общие проверки и handoff — по `AGENTS.md`.

## Источники
- `spec/architecture.md`: разделение models.py при росте без смены public imports.
- Новых операций OAS в этой карточке нет.
