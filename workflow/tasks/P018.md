# P018: Проверить полноту Pay и подготовить переход к Exchange

## Цель
Получить обозримый законченный Pay scope с честным отчётом о проверках и рисках.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `README.md`, `spec/pay-api.md`, `spec/test-plan.md`, `spec/architecture.md`.
- `spec/verification.md`, `workflow/tasks.json`, предыдущие handoffs.
- Фактические Pay public exports, ресурсы, request/response models и tests.

## Входит
- Сверить все 25 operations с sync/async public API, fixtures и источниками.
- Обновить примеры read/write/webhooks, документацию ошибок и ограничений.
- Проверить boundaries Pay/core/Exchange, package build и итоговый verification ledger.

## Не входит
- Публикация PyPI, live денежные операции, retries/auto-pagination без отдельной карточки.

## Приёмка
- На каждую из 25 операций есть один владелец в очереди и проверенный wire contract.
- Read/write/webhook примеры используют testnet и environment secrets без credentials.
- Offline pass, live pass/skip, unresolved API facts и непроверенные платформы различаются.
- Существенные найденные дефекты исправлены в пределах сессии либо задача передана незавершённой.

## Проверка
- Запустить `.venv\Scripts\python.exe -m pytest` и `.venv\Scripts\python.exe -m ruff check .`.
- Запустить `.venv\Scripts\python.exe -m mypy` и `.venv\Scripts\python.exe -m build --no-isolation`.
- Проверить соответствие inventory реальным тестам; не добавлять тест ради счётчика.
- Live GET возможен opt-in; отсутствие live mutations не маскировать mock результатами.

## Источники
- `spec/openapi/pay-current.json`: 18 paths / 25 operations исходного snapshot.
- `spec/verification.md`: дата, окружение и практические границы доказательств.
