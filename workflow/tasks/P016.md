# P016: Проверка подписи Current webhook по исходным байтам

## Цель
Дать stateless verifier Current webhook с корректной подписью и явной replay policy.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: §8 и ограничения clock skew/retry guarantees.
- Current OAS `#/info/description`; новый webhook модуль внутри Pay.
- Актуальные Pay error/export conventions; это отдельный secret от JWT.

## Входит
- HMAC-SHA256 ключом webhook secret: timestamp + '.' + raw body bytes.
- Signature-Timestamp в ms, Signature-Version v1, constant-time compare.
- Явно настраиваемое окно времени с тестовыми часами и отдельными webhook errors.

## Не входит
- Legacy SHA256(token) signing, JSON reserialization перед verify, dedupe storage, framework server.

## Приёмка
- Любое изменение подписанных bytes вызывает отказ; валидная подпись проверяется до JSON parsing.
- Missing/malformed headers, timestamp, version, signature, stale/future delivery покрыты.
- Выбранная tolerance — документированная policy SDK, а не придуманная гарантия API.
- Ни secret, ни полный body не попадают автоматически в repr/exception messages.

## Проверка
- Создать `tests/test_webhook_signatures.py` с детерминированными byte fixtures/clock.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_webhook_signatures.py`.
- Сеть, JWT и реальные webhook payload пользователя не нужны.

## Источники
- `spec/pay-api.md`: §8 Webhooks Current; Current `#/info/description`.
- Webhook delivery id dedupe остаётся ответственностью приложения.
