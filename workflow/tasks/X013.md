# X013: Contract gate private Exchange Transfers

Статус и зависимости — только в [очереди](../tasks.json). Карточка вне сохранённого
scope `ap-48ca458fcbf2`; ownership трёх операций обозначает только контрактный план.

## Результат

Проверенная граница transfers и отдельные малые implementation cards для read/write.

## Прочитать

- `AGENTS.md`, [контракт Exchange](../../spec/exchange-api.md), [X002](X002.md)
  и handoff X002 из [очереди](../tasks.json); official transfer docs по provenance.
- OAS POST/GET `/api/v1/accounts/transfers`, GET `/api/v1/accounts/transfer`,
  `TransferRequest`, `CreateTransferResponse`, `TransferResponse`, `TransfersResponse`
  и относящиеся errors/auth.

## Сделать

- Request: required asset/amount/from/to, optional clientTransferId (1–64);
  directions trading/funding. Проверить ограничения direction combinations по источникам,
  не выводить запрет from==to или idempotency guarantee только из enum/имени поля.
- POST success 201 и create statuses pending/completed отделить от GET 200 и
  retrieval statuses pending/completed/error; unknown response labels/fields сохранять.
  Numeric amount — Decimal; from wire field получает безопасное snake_case Python имя.
- Get требует transferId (1–20) или clientTransferId (1–64), при обоих wins transferId.
  List filters assets/from/to/startAt/endAt и numbered currentPage/pageSize; проверить
  limits/defaults, string timestamps, pagination shape независимо от Pay cursor.
- Явно записать, какие timeout/duplicate/client-ID guarantees отсутствуют. Будущий
  write не получает retries или автоматический resend после network error.
- Создать самостоятельные read и write cards, при необходимости ещё сузить; передать
  operation ownership новым owners ровно один раз и убрать дубли с gate.

## Вне scope

Реализация SDK transfers, реальные transfers, private HTTP/секреты, funding withdrawals,
account pooling с Pay и автоматическая reconciliation без подтверждённого контракта.

## Готово, когда

- Spec/карточки с источниками фиксируют ID precedence, pagination, request/response
  statuses и пределы гарантий; DoD будущих writes явно mock-only.
- Все три operations имеют единственного owner, новая очередь связна.
- JSON/provenance/link checks, `tools/session.py check`, handoff по `AGENTS.md` пройдены;
  planned coverage не выдаётся за implemented methods.
