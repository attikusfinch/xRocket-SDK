# X009: Exchange health

Статус и зависимости — только в [очереди](../tasks.json). Карточка вне сохранённого
scope `ap-48ca458fcbf2`; planned ownership одного GET не означает health monitor.

## Результат

Sync/async Exchange health resource читает GET `/health` без token.

## Прочитать

- `AGENTS.md`, [контракт Exchange](../../spec/exchange-api.md), [X002](X002.md)
  и handoff X002 из [очереди](../tasks.json).
- Exchange OAS `/health` целиком (response schema inline), фактические Exchange
  client/DTO и `_core/transport.py` policy для `/health`.

## Сделать

- Собственный Exchange DTO с required `status`, `info`, `error`, `details`.
  Все три component collections — arrays, required component fields `name`, `status`,
  optional `message`. Сохранить unknown fields/statuses; не импортировать Pay Health.
- OAS status values: ok/error/shutting_down, component up/down; единственный
  documented HTTP response — 200. Exact 200; не считать status=error HTTP ошибкой.
  Не добавлять Pay-specific или предположительный 503 success override.
- Поддержать обычные failures transport, non-JSON и invalid success response
  без вывода секретов; это SDK behavior, а не дополнительные OAS guarantees.

## Вне scope

Monitoring automation, polling, readiness aggregation и изменение Pay health policy.

## Готово, когда

- `tests/test_exchange_health.py` проверяет обе версии, `/health` вне `/api/v1`,
  empty arrays, all status values/unknowns, malformed shape и exact 200/non-200.
- Общие code/export checks `AGENTS.md`, workflow/link checks, spec и handoff выполнены;
  registry сохраняет отдельную Exchange operation независимо от Pay `/health`.
