# P003: Чтение платежей invoice и вложенных транзакций

## Цель
Читать страницу платежей invoice с корректными transaction types и finality.

## Прочитать
- `AGENTS.md` — общий протокол одной сессии; статусы берутся из `workflow/tasks.json`.
- `spec/pay-api.md`: invoice payments, pagination, PAY-004–007 и PAY-011.
- Актуальные invoice resource/model modules после P001, существующие identifier helpers.
- `spec/openapi/pay-current.json`: payment и transaction DTO.

## Входит
- `GET /api/v1/invoice/payments`: invoiceId/clientInvoiceId, cursor, limit.
- Модели InvoicePayment и внутренних/blockchain transactions с discriminator каждого item.
- Отдельная форма страницы допускает pagination.next без total.

## Не входит
- Создание payment address, webhook envelope, auto-pagination, трактовка unknown как paid.

## Приёмка
- Обе формы invoice ID и совместная передача сохраняют документированную семантику.
- Pending/null и finalized datetime читаются; необязательный payment id не становится required.
- Unknown response statuses/fields сохраняются; неизвестный transaction type обрабатывается явно.
- list выполняет один запрос; next=null завершает страницу независимо от размера items.

## Проверка
- Создать `tests/test_invoice_payments.py` для sync/async wire contract и сложных DTO.
- После создания: `.venv\Scripts\python.exe -m pytest tests/test_invoice_payments.py tests/test_models.py`.
- Реальные payment records и персональные данные в fixtures не добавлять.

## Источники
- `#/paths/~1api~1v1~1invoice~1payments/get`; `InvoicePaymentListResponseDto`.
- `InvoicePaymentDto`, `InvoiceInternalTransactionDto`, `InvoiceBlockchainTransactionDto`.
