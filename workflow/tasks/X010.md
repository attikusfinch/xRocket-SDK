# X010: Contract gate private Exchange Account

Статус и зависимости — только в [очереди](../tasks.json). Карточка вне сохранённого
scope `ap-48ca458fcbf2`; ownership — контрактный milestone, не обещание SDK методов.

## Результат

Проверенный spec и небольшие будущие implementation cards для private Account,
без реализации или запросов к аккаунту в этой сессии.

## Прочитать

- `AGENTS.md`, [контракт Exchange](../../spec/exchange-api.md), [X002](X002.md)
  и handoff X002 из [очереди](../tasks.json).
- Официальные overview/reference/auth источники по provenance spec и OAS только
  GET `/api/v1/accounts/trading/balances`, GET `/api/v1/trade-fees`,
  `TradingBalancesResponse`, `TradingAssetBalanceResponse`, `TradeFeesResponse`,
  `TradeFeeResponse`, `TradeFeeInfoResponse` и ошибки этих операций.

## Сделать

- Разрешить либо явно сохранить внешний вопрос trade-fees auth: OAS содержит bearer,
  reference не помечает этот метод как private. Не выбирать режим по догадке. Уточнить где
  private permission scopes/ограничения подтверждены, а где остаются неизвестны.
- Зафиксировать balances envelope и строковые asset/balance/available/holds;
  fees envelope, optional array query `symbols`, required `symbol`/`standard`,
  nested maker/taker numeric strings. Отдельные Exchange DTO и Decimal, без Pay reuse.
- Для каждой операции проверить exact success/error/auth contracts и составить
  обозримые будущие карточки с mock tests, independent credentials/session policy.
  Статус unresolved auth не маскировать как готовность к implementation.
- При разбиении перенести operation ownership с gate на новых единственных owners
  атомарно; сама завершённая gate получает `operations: []`, если все переданы.

## Вне scope

Private HTTP calls, secrets, account DTO/client implementation, orders/funding/WS.

- Spec перечисляет подтверждения и auth discrepancy с URL/date; каждый unresolved
  вопрос имеет понятный следующий шаг и блокирует только зависимый scope.
- Созданы малые implementation cards с точными paths/DoD, безопасным mock-only
  первым выполнением и зависимостью от этого gate; queue/ownership согласованы.
- JSON/provenance/link checks и `tools/session.py check` выполнены по `AGENTS.md`;
  новый handoff честно отделяет план от реализации и live проверки.
